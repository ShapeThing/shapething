# The ShapeThing Vocabulary (`st:`) — Draft Specification

**Status:** Draft / living document describing the `st:` namespace as implemented by
`@shapething/shacl-everything`. Not a published spec — it documents this package's extensions on
top of SHACL 1.2 Core and the [SHACL-UI](https://www.w3.org/ns/shacl-ui/) (`shui:`) proposal.

**Namespace:** `http://shapething.com/`, prefix `st:`.

## Built-in datatype sentinel: `<https://iconify.design>`

Not an `st:`-namespaced IRI (see `helpers/namespaces.ts`'s `iconifyDatatype`), but a ShapeThing
convention tied to `st:IconifyEditor`/`st:IconifyViewer`. A property declaring
`sh:datatype <https://iconify.design>` marks its value as an [Iconify](https://iconify.design/)
icon name (`"<collection>:<icon>"`, e.g. `"mdi:home"`) — the same identifier `@iconify/react`
resolves. It's a sentinel only: never dereferenced, and exists purely so those two widgets' own
scoring rules can recognize the value unambiguously.

## Property Roles extension: `st:GeoRole`

SHACL-UI §11 defines `shui:LabelRole`/`ClassificationRole`/`DepictionRole` — each naming which
`sh:property` on a value node's shape holds its label/classification/image (see
`resolution/label.ts`). `st:GeoRole` extends that same mechanism (still the object of the existing
`shui:propertyRole` predicate, not a new one) to mark which property holds a value's **geometry**,
consumed by `st:MapViewer`:

```turtle
ex:LandmarkShape
    a sh:NodeShape ;
    sh:property [ sh:path geo:asWKT ; shui:propertyRole st:GeoRole ] ;
    sh:property [ sh:path schema:name ; shui:propertyRole shui:LabelRole ] ;
    sh:property [ sh:path schema:additionalType ; shui:propertyRole shui:ClassificationRole ] ;
    .
```

All three roles are independent and optional — a value can declare `st:GeoRole` alone (geometry,
no tooltip) or combine it with either/both label roles. `resolution/label.ts`'s
`propertyPathsByRole(propertyShape, role)` is the shared, role-agnostic lookup underneath all four
roles.

## Property Roles extension: `st:ColorRole`

Marks which `sh:property` on a value node's shape holds a **swatch color** — consumed by
`shui:ClassificationRole`'s own chip (`AutoCompleteOption`/`Teaser`) and by `st:CategoryFacet`'s
option list. Unlike `st:GeoRole` and the three `shui:` roles above (all resolved via a
*property's own* `sh:node`/`sh:class`, i.e. what that property declares its values look like),
`st:ColorRole` is resolved off the value's **own** `rdf:type`: a `ClassificationRole` path can land
on a resource of a wholly different class than the enclosing property's own `sh:class` (e.g.
`skos:inScheme` landing on a `skos:ConceptScheme`, not another `skos:Concept`), so its color has to
come from a shape targeting *that* class, not the property's:

```turtle
ex:ConceptShape
    sh:property [ sh:path skos:prefLabel ; shui:propertyRole shui:LabelRole ] ;
    sh:property [ sh:path skos:inScheme ; shui:propertyRole shui:ClassificationRole ] ;
    .

ex:SchemeShape
    a sh:NodeShape ;
    sh:targetClass skos:ConceptScheme ;
    sh:property [ sh:path ex:swatch ; shui:propertyRole st:ColorRole ] ;
    .
```

`resolution/label.ts`'s `valueNodeColor({ term, propertyShape })` does the lookup: every node shape
`sh:targetClass`-ing one of `term`'s own `rdf:type` values (`ownClassNodeShapes`) is checked for a
`st:ColorRole`-annotated `sh:property`, walked from `term` itself. The resolved literal is used
as-is — typically a `colorDatatype`-typed hex string (see `st:ColorEditor`/`st:ColorViewer`), but
any CSS color string works. `CategoryFacet` applies the same lookup directly to each option value
(there's no separate "classification" hop there — the option *is* the value being colored).

## Node-level stylesheet import: `st:cssImport`

A `sh:NodeShape` can declare one or more `st:cssImport <URL>` triples to load extra, shape-authored
CSS whenever a focus node conforming to that shape is rendered (edit, view, or facet mode) - a
presentational escape hatch for styling that's specific to one shape (e.g. targeting one of its own
`sh:PropertyGroup`s by the `data-iri` every built-in group widget already renders) and doesn't
belong in this package's bundled theme:

```turtle
ex:ChefShape
    a sh:NodeShape ;
    st:cssImport <./chef-shape.css> ;
    sh:targetClass ex:Chef ;
    .
```

A relative URL resolves against the shapes graph document's own URL, the same as any other
relative IRI in Turtle. Each distinct URL is loaded as a single `<link rel="stylesheet">`,
shared and refcounted across every node currently rendering a shape that names it (see
`helpers/stylesheetRegistry.ts`) and removed again once no rendered node still needs it. When more
than one applicable shape (`sh:and`, several matching `sh:targetClass`es, an active facet root
shape, etc.) declares `st:cssImport`, every distinct URL loads, in that `nodeShapes` order - a
later shape's stylesheet cascades after an earlier one's. See `resolution/cssImports.ts`.
